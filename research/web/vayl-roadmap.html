Vayl · Strategy · North-Star & Roadmap

Vision big. Ship narrow.

Most AI memory accumulates — and hands agents facts that are no longer true. Vayl reconciles: it knows what's true now, forgets correctly, and can prove it.

"AI memory that knows what's true now — and can prove it."

This is the destination and the disciplined path to it. The vision is a platform. The execution is one wedge at a time — and the gate between every phase is demand, not features.

North-Star

The reconciling memory layer agents trust

Where this goes: the memory platform that agents in high-stakes work depend on — because it never acts on a fact that's been changed or retracted, it can show the audit trail of why it believes what it believes, and it keeps data where regulation requires it to stay.

What "winning" looks like

  • The default memory when an agent acting on the wrong fact is a real cost — health, finance, ops, compliance.
  • "Correct forgetting" and "current truth" become table stakes buyers ask for by name.
  • EU-sovereign by default — the one thing US incumbents can't relocate into.

Why us, not them

  • Additive stores (Mem0) can't say what's true now; they pile facts and rank stale ones first.
  • Graph stores (Zep) reconcile supersession but fail retraction and need heavy infra.
  • Vayl's edge is narrow and measured, not "better memory" hand-waving.
The wedge

One sharp thing, proven — not a feature list

We go big by starting narrow. The opening move is to win decisively on the axis where being wrong hurts: correct forgetting + current truth + audit.

Phased roadmap

You advance by usage, not by building

Each phase has a gate — a demand milestone you must hit before spending on the next. Features listed in later phases get built only when a user pulls them.

1

First users — the ONLY current focus

Now
  • Ship the MVP to 3–5 design partners in one ICP where correct-forgetting is acute (coding agents / personal assistants / sales-CRM — not healthcare first: great fit, brutal sales cycle).
  • Build only what a partner blocks on. Instrument usage so you learn what they actually hit.
Gate to advance: 3+ partners using it weekly, and at least one clear "I would pay for this." No revenue signal → stay here, don't build Phase 2.
gate ↓real, repeated usage + willingness to pay

Guardrails

The four rules that keep vision and execution aligned

1 · Vision big, ship narrow

Pitch the platform. Build the wedge. Never let the deck's scope leak into the sprint.

2 · Features are pulled, not pushed

Every feature is built because a real user blocked on it — not because a competitor's page lists it.

3 · Demand is the gate

You advance phases by usage and revenue, not by shipping more code. No signal = don't advance.

4 · Don't copy the incumbent

Their feature list solves their additive problems (bloat, sprawl). Half of it, we don't need — we reconcile.

Straight talk

What has to be true for any of this

Every phase past 0 depends on Phase 1. The engine is real and measured, but the numbers are single-run and suite-specific, and demand is still unvalidated — zero users so far. The whole roadmap is a bet that "correct forgetting + current truth" is a pain someone will pay to solve. Phase 1 is where that bet gets settled. Everything else is hope until it does.

The next commit that matters isn't code — it's the first design partner.
