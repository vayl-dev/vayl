# v0.5.0 — Performance, migrations and request IDs

_26 September 2026_

## Performance

* Tool calls no longer re-decrypt every row and re-parse every embedding. At 1,000 facts, with encryption on and model calls stubbed out, median `remember` drops from 122 ms to 23 ms and `recall` from 444 ms to 59 ms. Every hard delete clears the caches.

## Added

* **Request IDs.** Every `vayl-server` request gets an `X-Request-ID` (a plain incoming one is reused), stamped on every log line and on one access line per request.
* **Versioned schema migrations** recorded in `schema_migrations`, a version check that stops an older Vayl from running against a newer schema, and the `vayl-migrate status|up` command.
* `VAYL_LOG_FORMAT=json` and `VAYL_VECTOR_CACHE`.

## Changed

* Text log lines include the request ID in brackets after the logger name. Update log parsers or switch to JSON.

## Upgrading from 0.4

No action needed. The first start records the existing schema as v1 without changing data, and rolling back to 0.4.0 is safe.
