# v0.4.0 — Adapters, tenants and hardening

_26 September 2026_

{% hint style="warning" %}
**Breaking for misconfigured setups.** Several invalid settings that used to be silently reinterpreted now fail at startup with a message naming the variable. Read **Upgrading from 0.3** below.
{% endhint %}

## Added

* **Agent-framework adapters:** `vayl.integrations.langgraph`, `.openai_agents` and `.crewai` (extras `langgraph`, `openai-agents`, `crewai`). Vercel AI SDK and Mastra adapters ship in the TypeScript client.
* **Presets** `coding`, `assistant` and `sales`, alongside `clinical`, `finance` and `support`.
* **Tenant partitioning.** A principal's `tenant` filters every store query, so two organizations on one deployment never see each other's memory, even under the same `user_id`.
* `VAYL_LOG_LEVEL` (default `WARNING`); logs go to stderr.

## Changed

* Unknown `LLM_PROVIDER` or `VAYL_KMS`, `VAYL_KMS=vault` without `VAULT_TOKEN`, and malformed numbers now fail at startup.
* `health()` makes one attempt per dependency instead of backing off for minutes.

## Security

* **Erasure fails closed.** If the Neo4j purge fails, `delete` / `delete_all` erase nothing and issue no receipt.
* `NEO4J_PASSWORD` is required when the graph is enabled.
* Exception text no longer leaks: `stats()` shows error text to admins only, and `ERROR` logs carry a reference, the type and the location.
* `cryptography>=50` (PYSEC-2026-3552); `pyjwt>=2.13.0` for the `sso` extra.

## Fixed

* A declared single-valued slot supersedes the old value even when the extractor mislabels the change as an event.
* Mismatched embedding dimensions fall back to lexical ranking instead of producing a meaningless ranking.

## Removed

* `vayl.clinical` (FHIR ingestion). It was not wired into any tool. `preset:clinical` is unchanged.

## Upgrading from 0.3

1. Back up your database. The first start adds a `tenant_id` column and new indexes.
2. If the graph is enabled, set `NEO4J_PASSWORD`.
3. `LLM_PROVIDER` must be `openai`, `anthropic` or `groq`. For Ollama or vLLM use `openai` with `OPENAI_BASE_URL`.
4. `VAYL_KMS` must be `file` or `vault`; `vault` requires `VAULT_TOKEN`.
5. Code importing `vayl.clinical` must vendor it.
