# v0.6.0 — Approval gate, HTTP fix and correct defaults

_26 September 2026_

{% hint style="warning" %}
**Read Upgrading below.** Approving changes now needs the `approve` capability, and embeddings follow `OPENAI_API_KEY`.
{% endhint %}

## Security

* **Only a person can approve a gated change.** `confirm_change` and `reject_change` need a new `approve` capability, held only by the `admin` and `member` roles, so an agent can no longer approve its own proposal. The approver recorded is the authenticated caller; `decided_by` is only a note.
* **Trusted sources are bound to a key.** A write labelled with a `VAYL_TRUSTED_SOURCES` source skips the confirmation gate, so it is now accepted only from the key with that name or a key that can approve.

## Fixed

* **`vayl-server` returned an empty response to every MCP call.** The request-size middleware answered every read after the body with a disconnect, which cancelled each streamed response. stdio was not affected.
* The documented Docker admin bootstrap command now works (`-e VAYL_AUTH_REQUIRED=0`).

## Changed

* **Embeddings follow your OpenAI key.** With only `OPENAI_API_KEY` set, embeddings now go to OpenAI (`text-embedding-3-small`) instead of a local Ollama.
* **Every on/off setting is parsed strictly.** `on/off/true/false/yes/no/1/0` in any case; anything else fails at startup. Before, `VAYL_AUTH_REQUIRED=on` silently meant off.

## Added

* `vayl-mcp` and `vayl-server` answer `--help` and `--version`.

## Upgrading from 0.5

* Approve changes with a `member` or `admin` key; agent keys are now denied.
* An integration writing as a trusted source needs a key whose name matches the source, for example `create_principal("fhir", role="agent")`.
* If you set only `OPENAI_API_KEY` and ran a local Ollama for embeddings, set `EMBED_BASE_URL=http://localhost:11434/v1` to keep using it.
* Local stdio use is unaffected.
